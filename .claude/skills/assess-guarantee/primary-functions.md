# quenta の機能

`assess-guarantee` スキルで、性質の「機能への影響」を決めるときに使う一覧。主要な機能は、「これができないなら、quenta を使う意味がない」もの。主要か副次かは、人（プロダクトオーナー）が決める。新しいストーリーで機能を足すときは、`implement-story` の手順 2 で人に聞き、ここに足す。

## 主要な機能

| 機能 | 関係するストーリー |
|---|---|
| 残作業を漏れなく知る | #1 |
| 状態の変更と、その経緯を残す | #1 |
| 複数のセッションが、取り合わずに作業を取る | #2 |
| 前提のタスクが終わるまで、後のタスクを取らせない | #3 |
| 作業を途中でやめても、別のセッションが続きをやれる | #4 |
| 取ったまま終了したタスクを、取り戻せる | #6 |
| 人の判断待ちを知らせる | #7 |

## 副次的な機能

| 機能 | 関係するストーリー |
|---|---|
| プロジェクトごとに分ける | #5 |
| 古い終わったタスクを掃除する | #8 |
| Claude Code のセッションから、設定なしに使える | #9 |
| DB の不整合を検知し、経路を辿り、調査する | #18、#19、#20 |
